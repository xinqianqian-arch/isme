# 课时备课文章（教材目录）

**样板**：`src/content/lessons/人教-三上-线段射线直线.md`。用户在 2026-11-06 确认它就是标准。动笔前先通读一遍，结构、语气、深度照它来；配图按需判断，不照抄它的位置和数量。

## 定位

- **读者**：小学数学老师，备课、写教案、说课、上公开课时来查。
- **目标**：老师读完能直接上课，并愿意去小红书看、买配套的互动课件和 PPT。
- **位置**：放在教材目录下，网址是 `/textbooks/<版本>/grade-N/volume-V/unit-NN/lesson-NN/`。“教学文章”栏目写的是 AI 使用分享和思考，不放课时讲解。
- **版式**：标准 Markdown，读起来像飞书或 Notion 文档。不写 HTML，不用 emoji 装饰。以后要同步到公众号。

## 流程

1. 吃透教材，核对事实（第 1 节）。
2. 建文件、写开头信息（第 2 节）。
3. 按固定结构写正文（第 3、4 节）。
4. 配图：正文写完后逐段判断哪里需要图，不定数量、不定位置；每课至少一张黏土风插画，保持风格统一。见 [images.md](images.md) 的“按需配图”。
5. 构建、截图检查、提交（第 5 节）。

## 1. 先吃透教材（不准编）

- **课题和顺序**：课题、单元名和先后顺序以 `src/content/textbooks/<版本缩写>/<年级册>.yaml` 为准。
  - 要写的课不在 `课时` 列表里，就先补进列表。
  - 已有的顺序不要动，顺序决定网址编号。
- **教材细节**：页码、例题、“做一做”和练习题号都要来自教材本身，比如用户提供的电子课本（国家中小学智慧教育平台）。拿不准就不写具体页码或题号，并告诉用户哪些需要核对。
- **查资料的线索**（北师大三下实测有效）：
  - 搜狐常有转载的新版课本整本页图，比如北师大三下 https://www.sohu.com/a/977462951_121290829 ，页脚印着页码；
  - 21 世纪教育网（zy.21cnjy.com）的“全册教案”会写明各课在教材第几页；
  - 搜狐转载的《教学月刊》单元解析，会讲新教材增删了哪些课、为什么改；
  - 教习网、原创力文档上的课件简介可以佐证例题数据。
  - 资料之间说法不一致时，以课本页图为准。
- **动笔前想清楚三件事**：
  - 前后联系：学生已经学过什么，本课学什么，后面哪里要用到。
  - 新旧教材变化：2024 年起新版教材做了什么调整，对备课有什么影响（比如学生小了一岁）。
  - 编排意图：教材用什么线索把知识串起来，教学就沿这条主线走。

## 2. 文件和开头信息

**文件名**：`src/content/lessons/<版本简称>-<年级册简称>-<课题>.md`，比如 `人教-三上-线段射线直线.md`。复制同目录的 `_模板.md` 起步。

| 字段 | 怎么写 |
| --- | --- |
| `教材` | `人教版`（不写默认北师大版） |
| `年级`、`课题` | 和教材目录 YAML 一字不差 |
| `标题` | `<版本><年级册>《课题》教学设计：教材分析、教学目标、重难点与 AI 互动课件` |
| `知识点`（可选） | 列表卡片和找课搜索里显示的知识点；不写就从 `标题` 里《课题》后面、“教学设计”前面那段自动取，所以标题里的知识点要写成老师会搜的词 |
| `大标题` | `《课题》怎么教？<版本><年级简称>新教材备课全解` |
| `简介` | 80–120 字，说清这一课属于哪个单元，覆盖了哪些部分；会显示在搜索结果里 |
| `日期` | 当天日期 |
| `页码`、`课型` | 例如 `第 61–62 页`、`概念课 · 1 课时（40 分钟）`；页码拿不准就不写 |
| `核心素养` | 2–3 个，例如 `[空间观念, 抽象能力, 推理意识]` |
| `图标` | 贴纸名，如 `o02`（R2 上 `brand/stickers/` 下的文件） |
| `封面` | `https://media.11aike.com/<这一课的网址路径>/cover.webp`，1200×630 |

## 3. 正文结构（固定 10 节 + 常见问题）

开头先写一段引用：`> **一句话备课结论**：……`，说清教什么、真正的难点在哪。

| 小标题 | 必写内容 |
| --- | --- |
| `## 一、教材解读` | 三个三级标题：`### 前后联系`、`### 新旧教材变化`、`### 编排意图` |
| `## 二、学情分析` | **已有基础**；**可能的困难**（编号列出，具体到学生会怎么错） |
| `## 三、教学目标与重难点` | 目标 3–4 条，每条末尾括号标核心素养；**教学重点**、**教学难点** |
| `## 四、教学过程` | 每个环节一个 `### 1. 环节名（N 分钟）`，时间合计 40 分钟；见下方说明 |
| `## 五、趣味设计` | 3–4 个能直接用的活动：身体动作、游戏、口诀、贯穿全课的故事线 |
| `## 六、AI 赋能` | 全文的重点，见第 4 节 |
| `## 七、板书设计` | **每课一张小黑板板书图**（网站特色），用 `scripts/board.py` 生成，见 images.md 的“小黑板板书”；可以在图前用一两句话说明板书结构 |
| `## 八、分层作业` | **基础 / 提升 / 挑战**，答案要点写在括号里 |
| `## 九、易错点与应对` | 错误表现 → 原因 → 应对；对比能说清楚时配正误对比图 |
| `## 十、反思与说课` | 反思看什么（学生说不说得出理由），说课突出什么 |
| `## 常见问题` | 5–6 组问答，见下方说明 |

**教学过程**：
- 每个环节都写清关键提问（加粗）、学生可能怎么回答、操作步骤。
- 至少有一处 `> **设计意图**：……`。
- 导入和小结要前后呼应。

**常见问题**：
- 格式：`**问题？**` 单独一行，下一行写回答。网站会自动标注成 FAQ 结构化数据。
- 必须包含：
  - 导入怎么做；
  - 难点怎么突破；
  - 一个易混问题；
  - 新教材为什么这样编；
  - AI 最该用在哪；
  - 有没有互动课件或 PPT（链接到小红书主页，地址见 `src/site.config.ts` 的 `xhs.profile`）。

## 4. 写作规范

### AI 赋能（用户最看重，要写深）

- 开头一段先讲清立场：AI 赋能不是把 PPT 做炫，而是落在老师最费时间、又最难做好的事上。比如摸清学生真实的想法、把抽象概念变成可以操作的东西、让每个学生拿到适合自己的练习。
- 固定用五个三级标题：`### 课前：学情前测`、`### 课中：……`、`### 课后：分层练习`、`### 教研：AI 听课伙伴`、`### 使用边界`。
  - “课中”的副标题按本课内容起，比如“先想象，再验证”。
  - 每个三级标题下第一句话用加粗写结论。
- **每一条都具体到这节课**。不要写“AI 可以生成练习”，要写“针对‘射线端点字母写反’出 6 道读写题”。
- 至少 3 段可以直接复制的提示词，放在代码块里，写明版本、年级、课题和要求。网站会给代码块加“复制”按钮。
- 必须写到这几个原则：
  - 先让学生想，再用课件验证；
  - 演示不替代思考；
  - AI 出的内容由老师核对教材、检查有没有超纲。
- 本节最后一段自然引出十一课件的互动课件，说清它是按这套思路设计的。

### 小标题、关键词与语气

- **小标题要短**：
  - 二级标题不超过 10 个字，比如“一、教材解读”。三级标题一行写完。左侧目录直接用这些小标题。
  - 生动的说法放到这一节第一句，加粗开头，比如“**一束光能照多远？**”。
  - 需要用问句回答的内容，放到“常见问题”里。
- **关键词自然覆盖**（为了 SEO/GEO，但不要堆砌）：教学设计、教案、教材分析、学情分析、教学目标、教学重难点、核心素养、新旧教材对比、导入、板书设计、分层作业、易错点、说课、教学反思、互动课件、PPT、AI。
- **加粗别以标点结尾**：`**……？**` 后面紧跟汉字时，加粗会失效，页面上直接露出星号（“？”“：”“×”和引号都算标点）。把标点移到星号外面，写成 `**……**？`。
- **写明位置**：版本、年级册、第几单元“单元名”、第几课时。
- **语气**：专业、亲切，像同行之间分享经验。多用短句和列表，一段只讲一个意思。
- **不要写的**：
  - 削弱购买意愿的话，比如“制作中”“暂未提供”“不代表可购买”；
  - 夸大其词，比如“全网最好”“必考”。
- **篇幅**：样板约 6000 字，内容扎实优先，不凑字数。

## 5. 检查与提交

1. 运行 `npm run build`，必须通过。构建检查会报出写错的字段、找不到的图片和课题。
2. 本地打开页面，分别看电脑（1440 宽）和手机（390 宽）：
   - 左侧目录不换行；
   - 示意图文字看得清；
   - 表格在手机上可以左右滑动；
   - 图注正确。
3. 在需求分支上提交并推送。需要给用户预览时，运行 `npx wrangler deploy --env preview`，发布到固定的预览网址 https://11ai-preview.xinqianqian951210.workers.dev（每次覆盖，不影响线上；不要再用 `wrangler versions upload`，它会留下一堆清不掉的版本网址）。
   - 这一步要用 Cloudflare token：先 `set -a; source /home/ec2-user/jnb/.env.cloudflare; set +a`（本机文件，权限 600，不在任何仓库里；R2 上传、清缓存、发布 Worker、glbgpt 配图的 key 都在里面）。
4. 推到 `main` 就是上线。用户已授权（2026-11-07）：改完检查没问题就直接合并到 main 上线，再核对线上；需要用户拍板的事（按未出版教材写、删页面、改设计方向等）先问。
5. **任何 key 和 token（Poe、Cloudflare、glbgpt）都不能写进仓库文件或提交**；只放在 `/home/ec2-user/jnb/.env.cloudflare`，用的时候 source 进环境变量。派助手时 key 写在派活消息里（助手自己读这个文件会被权限检查拦下），不要抄进简报、提示词文件或临时文件。
